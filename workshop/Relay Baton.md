# Relay Baton

Shared handoff between Claude Code and Codex for Benecles's ongoing projects. Read this before taking over a project, then update it before passing the work back. Keep entries short, factual, and current. This file is a coordination note, not a substitute for reading the actual files and checking their state.

## Why this exists

Benecles alternates between Claude and Codex as usage limits and the work demand. Claude is currently his preferred model for judgment-heavy, quality-critical work and is especially important for his internship; preserving Claude's quota matters. Codex is useful as an architect/orchestrator for study and personal projects, especially when it can assign repetitive, high-volume work to cheaper Luna agents and review their output. Preferences may change as models change. Neither agent should redo finished work merely because the other produced it; inspect it, keep what holds up, and fix what does not.

The desired rhythm is: record a work batch **when it starts**, update it at meaningful milestones, and mark it done only after checking the result. Usage can end abruptly. The next agent reads the last started entry, inspects the actual files, and continues from what really landed. A handoff is not a claim that unreviewed drafts are finished.

## Shared rules

- Follow the user's current instructions first. This file describes the working arrangement; it does not override a newer request.
- Before editing, check `/Users/benecles/Documents/agents/` for active instance status and claimed paths. Do not collide with another active worker. Use that folder's live registry convention for your own substantive run; subagents do not create separate registry files.
- Use Luna for bulk extraction, classification, rewriting, formatting, and similar independent batches when available. The primary Codex agent defines briefs, handles judgment-heavy decisions, reviews results, and integrates the work.
- Preserve source material, uncommitted changes, and unrelated files. Record exactly what has been committed or published; local drafts and live pages are different states.
- Other people are now using the live study site and giving feedback. Keep downtime and broken intermediate states to a minimum: prepare and QA changes in an isolated checkout, publish a coherent verified version rather than half-finished pages, check the live pages immediately afterward, and be ready to revert a bad deploy. Apply this to both courses and site-wide changes; it is a practical deployment priority, not a reason to leave good improvements unpublished indefinitely.
- For study sites, the syllabus is the coverage contract. Inspect slide images as visual sources, use assigned books for depth, build diagrams only when they explain something, and check the pages on desktop and phone. Public pages should teach directly: no visible citations, slide pins, provenance panels, or build-process narration. Keep a private source ledger for audit.
- **No cloud AI on scanned pages (Benecles, 2026-09-25):** no cloud model (Claude, Codex, Luna, any other) reads images of scanned notebooks, books or friends' notes. The page-capture pipeline is fully local, and QA runs on metrics plus a human look.
- **Tesseract-only scan extraction for these course-prep batches (Benecles, 2026-09-27/28):** scans and photos are processed with local Tesseract, not Apple Vision or another vision model. The Metodologia original-exam batch initially used Apple Vision for some PNGs; Sol7 ordered removal and Tesseract-only regeneration. Do not use the original 120-row exam batch until its correction is complete.
- **Design authority (Benecles, 2026-09-25):** Claude owns the CUFRGS look and feel: layout, figures, motion, menus, PDFs, any new UI. Codex can and should do visual work when it saves time, but it builds to Claude's direction (exemplars, specs), and its output is provisional until Claude reviews and refines it. Don't publish Codex-styled UI unreviewed.
- **Source atoms and lesson dependencies (Benecles, 2026-09-28; standing protocol):** Before a lesson writer drafts, split each authoritative book/article into complete TOC or body subsections or focused document spans, normally around 20–40 PDF pages or less. Keep exact original path/hash, edition, heading, and PDF/printed page bounds. Map each atom to the specific syllabus lesson(s) that need it. A writer receives a manageable required set (normally at most around 60–80 source pages); if more is genuinely needed, split the work by topic and integrate afterward. The lesson plan lists required and optional atoms, plus precise concepts inherited from earlier lessons. A short, source-linked predecessor handoff carries those concepts forward; it does not replace an original for new claims. Require a reading receipt for the assigned atoms before drafting. Never replace full sections with keyword-hit snippets, peer notes, or model memory. This is the default for future courses and for any later retrofit of content built before this protocol: map existing claims to atoms and dependencies, then flag unsupported or oversized units for targeted repair. Do not commission a separate broad audit *now* solely to apply it; the retrofit of older content happens in the **post-build global conformance audit** (see "Planned: global conformance audit" below).
- **Read text as text, never page by page on screen (Benecles, 2026-09-28):** Don't read documents through computer use, browser screenshots or page-by-page viewing: it burns tokens on images and misreads text. Computer use is fine for *navigating* (logging in, finding and clicking a download). To *read* anything (PDF, Moodle page, court decision, article), download or save the file, extract its text locally (pdftotext, textutil, the webarchive's HTML, or local Tesseract for scans), and read the extracted text file. A few verification screenshots are fine; hundreds of pages through the screen are not. This doesn't override the no-cloud-vision-on-scans rule: scans go through local OCR, never through a vision model.
- **Polish layer (Claude, 2026-09-28):** hand edits to generated pages are stored as exact before→after patches in `study-lab-publish/tools/polish/<page>.json` and reapplied automatically after every `kit.page()` write (and after the Delito wrapper). Regenerating a page is therefore safe. If you rewrite a page's *source text*, some patches may stop matching: run `python3 tools/polish.py check` in the publish checkout and report pages with unlocatable edits. Don't delete the polish folder.
- **Asset versions are automatic (Claude, 2026-09-29):** `tools/offline_build.py` now runs `tools/assetver.py`, which rewrites every course page's `assets/<name>.css|js?v=…` to a hash of the file. Don't hand-bump `?v=` anymore. Course `curso.css`/`curso.js` (and Controle's `controle.*`) also carry the phone tap-to-tuck figure behaviour (`.stage.tuckable`, `body.figs-tucked`); keep it if you touch those files.
- **Landscape = desktop (owner, 2026-09-29):** a device wider than it is tall gets the desktop layout. `tools/landscape.py` (run by offline_build) appends `and (orientation:portrait)` to every `@media … max-width …` rule and JS `matchMedia('(max-width:…)')`. Write narrow rules normally; don't design a separate landscape-phone layout.
- **Find, don't freeze (Benecles + Claude, 2026-09-28):** "Never invent" means go find the source, not stop working. Before holding any unit: (1) search every local course folder and your own batches, not just the course's own folder; (2) fetch public primary sources yourself (STF/STJ inteiro teor, Planalto, open-access journals), recording URL and date; (3) if the assigned reading is missing but the base books and statute cover the topic, build from those and note the gap in the ledger; (4) treat readable OCR and edition differences as ledger caveats, not blockers. Hold a unit only when no authoritative source exists anywhere reachable, or when the texts aren't posted or published yet.
- **Data prep is a separate gate (Benecles, 2026-09-28):** Do not start lesson writing simply because files are downloaded. First finish the authoritative syllabus/resource map, source provenance and local extraction, chapter/topic atoms, lesson-to-atom classification, prerequisite links, and explicit missing/uncertain-source ledger. A later writer receives only the bounded packet for its own topic and passes the reading receipt. If this gate is incomplete, mark the lesson blocked or provisional rather than filling gaps from general knowledge. Apply the same gate when older content is next revised.
- If work is paused, stop workers and leave a clear next-action list. Do not quietly publish unfinished work.

## Build-process lessons (read before launching any Codex run; add a line whenever we learn one)

Measured lessons about *how* we build. Each entry is a rule, followed by the evidence behind it. Update entries in place; don't bury them in the work log. The same rules live in `~/.codex/AGENTS.md` (ORCHESTRATOR ECONOMY) so Codex sees them automatically.

- **Default Codex setup (owner, 29/09):** a headless `codex exec -m gpt-6-luna -c model_reasoning_effort=high` orchestrator with Luna-**medium** workers. Claude writes the brief (judgment calls made up front, plus a mechanical check script) and gates the result. Sol is out of the loop; bring it back through the CLI only if Luna orchestration proves subpar. *Evidence:* Sol was ≈85% of Codex spend, mostly re-reading its own long context and polling (770 of 3,467 calls were polls).
- **Spawn workers with `fork_turns: "none"` and no model/effort arguments (29/09).** An omitted or `"all"` fork gives the worker the orchestrator's entire history **and** its model and effort, which can't then be overridden. *Evidence:* 23 sessions, all Luna-high, each call re-reading 50–100k tokens. That was 27M input tokens and **+8% of the Codex 5-hour window in 11 minutes**.
- **The orchestrator stays small; inspection goes to workers (29/09).** Worker transcripts do *not* flow back (replies ≤2.5k chars). The D1 orchestrator still grew from 18k to 113k of context because it looked at 28 gate screenshots and did fix rounds itself, and every later call re-read that. Screenshots, big files and fix rounds go to a fresh worker, which returns a ≤5-line verdict.
- **One orchestrator = one fresh session per order.** Complete briefs, spawn the batch, then ONE long wait. No polling (`wait_agent`/`list_agents` loops).
- **Workers can claim "done" without doing anything (29/09):** 3 of 16 Luna workers in a trivial test replied "done" with no file written. Every brief needs a done-condition that a script checks (file exists, checker exits 0). That's an existence check, not an audit.
- **Script the mechanical part yourself; Luna only fills in judgment (29/09).** D3: Claude generated the 220-row skeleton (page, figure, caption, panels) with a script and a checker that rejects invented, changed or missing rows. Luna only filled boxy/genre/reason. It passed 220/220 in about 10 minutes.
- **Goal budgets:** the goal tool works in `codex exec` when the prompt tells the agent to create a goal. The budget counts real tokens: a trivial 16-worker test used about 53k and stopped as `budget_limited`. Size budgets from the ledger.
- **Parallel runs share one 5-hour window.** Four simultaneous orchestrators can fill it in about 1.5 hours. On a usage wall: wait for the reset, then `codex exec resume <id> "continue"`.
- **Tiny items: Claude just does them.** Anything around 20 lines (D4) costs less than a Codex round trip.
- **Generators can be stale relative to live (29/09).** Delito's `s17.py` output differed from the live page because of later hand edits. Before regenerating any page, diff the output against live (with `polish.py apply`). Otherwise patch the live HTML and record the edit with `POLISH_BASE=<commit before> python3 tools/polish.py capture <files>`.
- **Browser caching during gates:** the preview pane caches assets. Before judging a JS change, run `fetch(url,{cache:'reload'})` and then reload. The live site is safe because `assetver` hashes change on ship.
- **A word drop on ship means check for lost content (29/09).** When D1 shipped, live words fell by 1,169. The ledger caught it: the new front template had silently dropped the one-line lesson descriptions (Const I went from 2,034 words to 580). They were restored for 81 lessons. Compare per-page word counts old vs new before accepting any template swap.
- **Management is a script, not a model (30/09).** `work/program/runner.sh` is a zero-token shell loop: queue.tsv → a fresh Luna-high orchestrator per order (preamble.md + orders/<id>.md) → mechanical check → retry once → sleep through 5h walls → stop near the weekly limit. A Luna-**xhigh** program manager (pm.md) is woken only when nothing is runnable or an order fails twice. It writes redo/next orders and `claude-inbox.md`. Claude only writes briefs, gates and ships (redo requests go in `claude-requests.md`). Owner reason: Claude was spending its scarce tokens on process babysitting.
- **A check must fail on the known-bad state before you trust its pass (30/09).** D2 fix 1 made the plate worse yet passed `check_plate.py`, which only checks sourcing and text. Now every visual order carries a geometry check (`d2/check_collisions.py`, `gates/jank.mjs`), and Claude runs each new check once against the bad version to see it fail.
- **Claude's own long session balloons too (30/09).** By 03:00 this orchestrating Claude session carried about 430k tokens of context, so every call re-read all of it. Gating goes to FRESH scheduled Claude sessions (the 3x-daily gate task), and the long session stays a light supervisor. Start a new Claude chat per working day, with the baton + Claude1.md as memory.
- **iCloud evicts work files (30/09).** ~/Documents syncs to iCloud with Optimize Storage, so background processes (the ship watcher, headless agents) hit `OSError: [Errno 11] Resource deadlock avoided` or hanging reads on evicted files, while foreground shells can materialize them. Fix: in Finder, right-click ~/Documents/Codex → "Keep Downloaded" (owner action). Until then, foreground ship runs are the reliable path; `shipper.py` treats Errno 11 as retry-later.
- **Genre names don't cure boxes (30/09).** Luna repeatedly relabels box-and-arrow charts as "genealogy", "flowchart" or "blueprint". The rule now in program/preamble.md: text in rectangles joined by arrows is banned in every genre, and only true grids (decision table, form, ledger) may hold text in cells. Claude rejects on sight.
- **Disk full → iCloud eviction → total stall (30/09).** Overnight gate screenshots (about 1.7 GB of PNGs) plus Codex session logs (4 GB) filled the disk to 116 MB. Writes failed, and macOS evicted iCloud copies of the work tree, so background processes could no longer read even runner.sh ("Operation timed out"). Recovery: free space, `brctl download <dir>`, read-test, restart. Prevention: crops only, captures in /private/tmp, no full-page screenshots (program/preamble.md).
- **`pkill -f runner.sh` kills the shell that runs it (30/09).** The pattern matches the calling command's own text, so the restart killed itself and all runners, and orphaned three orders in "running". Use `pgrep -f "work/program/runner" | xargs kill` from a script file, or kill by pid, then reset orphaned `running` states to pending.
- **Measure it:** after each ship, run `python3 work/usage/ledger.py <claude5h%> <claudeweek%> "note"` (Claude % from the app's usage card or `get_usage`). It logs Codex %, Codex tokens since the last row, and live/staging word counts, so we can tell what each feature costs.

> **Word count is only a smoke alarm, never a target.** Teoria do Delito sits around ~6k words per unit, so a lesson far below that is probably *missing content*: find what's missing and add it. If a topic is genuinely covered in 3k words, 3k is correct. Report depth as "what was added" (positions, cases, examples), not as word counts.

Pipeline:
1. ffmpeg frames.
2. Stillness and sharpness scoring (frame difference plus Laplacian variance) to pick one sharp frame per spread; dedupe with a perceptual hash.
3. Detect the spread and correct perspective.
4. Split at the gutter and dewarp the page curve.
5. Illumination normalisation.
6. OCR: Apple Vision for print and handwriting; Tesseract as a second opinion on print; vocabulary correction from the course texts. All local.
7. Page-number continuity check that flags missing pages; contact sheet for a quick human check.
8. Output: searchable PDF plus per-page text, into a prep folder.

Capture advice: phone on a stand, even light, 4K, a pause of about 1 s on each spread.

## How to pass the baton

When beginning a substantial batch, write its live-log entry **first**. When handing off an active project, update its entry with:

1. **Who worked and when:** Claude, Codex, or subagent batch; date.
2. **Exact paths and ownership:** repository, source folder, files being edited, other active claims.
3. **What changed:** concrete files/features/content, and whether changes are local, committed, pushed, or live.
4. **What was checked:** commands, browser widths/pages, sources verified, known limits.
5. **What remains:** a prioritized, actionable list, including any unresolved factual or design decisions.
6. **Where to resume:** the next specific action, not just “continue.”

Keep a short history below this section if multiple handoffs occur. Avoid secrets, personal identifiers, raw usage data, and enormous transcripts. Link to detailed notes rather than copying them here.
